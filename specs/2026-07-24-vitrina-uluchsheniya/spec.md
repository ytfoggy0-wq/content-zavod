# Спека: улучшение витрины content-zavod

## Цель
Сделать `app.py` понятнее визуально (карточки вместо плоской таблицы), добавить превью-картинку
и описание видеоряда к каждому ролику, не усложняя фильтры. Плюс бейдж для топ-score роликов.

## Решённые развилки
1. Превью для старых 203 роликов — прямой запрос к странице `reel_url`, парсинг `og:image`
   (без Apify, без траты лимита).
2. Превью для новых роликов — `thumbnailUrl` уже приходит из Apify-актора, начинаем сохранять.
3. «Описание видео» — thumbnail → Groq vision-модель → 1-2 предложения в `video_description`.
4. Фильтры не меняются по составу (аккаунты + мин. score) — фокус на визуальном упрощении.
5. Доп. идея (утверждена): бейдж/выделение для роликов с топ-score.

## Куски работы
| # | Что делаем | Файлы |
|---|---|---|
| A | Добавить колонки `thumbnail_url`, `video_description` | `sql/schema.sql` + ALTER на реальной БД |
| B | Сохранять `thumbnailUrl` из Apify при insert/update | `src/collect_reels.py` |
| C | Догнать превью для роликов без него через `og:image` со страницы IG | `src/fetch_thumbnails_ig.py` (новый) |
| D | Сгенерировать `video_description` через Groq vision по превью | `src/describe_reels.py` (новый) |
| E | Редизайн витрины: карточки, пагинация, бейдж топ-score | `app.py` |

## Приёмочные тесты
- A: `\d reels` в psql показывает `thumbnail_url text`, `video_description text`.
- B: код-ревью подтверждает запись `thumbnailUrl` в обе ветки upsert; живой прогон — когда
  восстановится лимит Apify.
- C: прогон на реальных 203 роликах — растёт доля заполненных `thumbnail_url`, ошибка на одном
  ролике не роняет весь батч (лог "успешно/ошибок" в конце).
- D: прогон на батче из 10 роликов — у всех непустой `video_description`, батчинг с паузами.
- E: `streamlit run app.py` открывается, карточки показывают картинку (если есть), score/views/
  likes, video_description, transcript в экспандере, бейдж у топ-score роликов; фильтры
  работают; пагинация ограничивает единовременный вывод.
